Rcmake

A clean-room CMake 4.5.1 replacement written in safe Rust. Single binary for cmake, ctest, and cpack.

$ git clone https://github.com/dvgyl/Rcmake && Rcmake/scripts/install.sh --alias-cmake
$ cmake -S . -B build -G Ninja && cmake --build build

The installer downloads the latest release into $HOME/.local. --alias-cmake adds cmake, ctest, and cpack links to rcmake.

Architecture

The workspace has 34 crates. Each stage of a configure run is a separate crate.

CMakeLists.txt
  -> rcmake-syntax     lex and parse
  -> rcmake-eval       commands, variables, policies, generator expressions
  -> rcmake-resolve    targets, usage requirements, link graph
  -> rcmake-gen-*      build.ninja, Makefile, project.pbxproj, .vcxproj

   all stages read files, environment, processes, and time through Host
   NativeHost = real builds          PureHost = tests, editors, wasm32

Every crate has #![forbid(unsafe_code)]. Input from CMakeLists.txt, caches, presets, and process output is untrusted. The parsers have limits on recursion, expansion, and file size, and they do not panic.

The Host trait is the only access to the operating system. Tests use PureHost, an in-memory host, so they are fast and give the same result each time. The browser playground uses the same host.

Known differences from CMake 4.5.1

  • There is no ccmake terminal interface, cmake-gui, DAP --debugger, or legacy extra generators (CodeBlocks, Eclipse CDT4, Kate, Sublime).
  • cmake -E tar and CPack archive generators write reproducible uid/gid 0 instead of host file ownership.
  • Some Tests/RunCMake cases still give different output. The compatibility report shows each suite.
  • Swift sources are accepted, but they are not yet verified against CMake 4.5.1.
  • When you run the binary as rcmake, it accepts extra options: --profile, --no-probe-cache, --fetch-lock, --hermetic, and the rcmake explain command. When you run it as cmake, output follows CMake format.
